**TileStar** runs DeepSeek V4 Flash on Apple M5 Max hardware.

The Metal-only build of `ds4-server` is a single self-contained file, under
1 MB, so it fits a **1.44 MB floppy disk** with TileLang-generated Metal
kernels embedded. It is built and tuned for one machine (an M5 Max with 128 GB
of RAM) and one model, and it exists for fun and to show the size the engine
can reach.

## Upstream

This project is based on upstream
[`antirez/ds4`](https://github.com/antirez/ds4) (DwarfStar), at commit
`0aaea5a238fb41a35106a551e73c8409dfb751ac` ("Document physical Metal TP
QA preflight and native batch coverage", 2026-09-20). Everything after
that commit here — the TileLang Metal kernel migration, the
machine-specific trimming, and the embedded-kernel single-file build — is
demo work. The upstream project supports more models, vision input, CUDA and
ROCm backends, SSD streaming for smaller machines, and distributed execution;
this branch keeps the Metal path for DeepSeek V4 Flash only.

**TileLang exception.** The `tl_*` Metal kernels are not hand-written:
they are generated by a **custom TileLang fork** (based on TileLang
0.1.15), not by upstream TileLang. The fork is not published; the
generated sources are checked in (`gen/metal/tl_*.metal`), so building
and running the server needs no TileLang at all. The custom additions
over upstream TileLang, used by the generator
(`tilelang-kernels/gen.py`), are:

- a **Metal codegen target** emitting self-contained MSL (`kernel void`
  entry points, buffers as `[[buffer(i)]]`, scalars packed into a
  `constant <name>_args_t&` struct, launch metadata as PrimFunc
  attributes),
- a pass-config switch (`tl.disable_index_legalize`) keeping grid
  indices 32-bit — Apple GPUs have no 64-bit integer ALU, and TileLang's
  default int64 index promotion alone cost ~3x on the first kernel,
- a two-level simdgroup AllReduce lowering (shuffle, one threadgroup
  exchange, shuffle) instead of the 10-barrier butterfly,
- a **CPU `c` target** (serial-loop lowering) used as a correctness
  reference for the kernel tests.

## Start here

```sh
make                             # builds ds4-server (and the other tools)
./download_model.sh ds4f-q2      # DeepSeek V4 Flash Q2, into gguf/
./ds4-server --ctx 32768
```

The server listens on `http://127.0.0.1:8000` and speaks the OpenAI chat,
OpenAI Responses and Anthropic Messages APIs; see [serving](docs/SERVER.md) and
[coding-agent clients](docs/CLIENTS.md). Downloads resume if interrupted. The
default model is `ds4flash.gguf`, a link updated by main-model downloads; pass
`-m FILE` to choose explicitly.

The same engine also builds `ds4` (interactive CLI, `./ds4 -p "..."`),
`ds4-agent`, `ds4-bench` and `ds4-eval`; run any of them with `--help`.

## The single-file server

The engine, the Metal kernels (TileLang-generated, plus two no-op housekeeping
kernels) and the TileLang tuned configuration are embedded in the binary,
compressed. The result is under 1 MB (923,288 bytes at the time of writing),
about 550 KB below the floppy's capacity. The server needs nothing beside the
model GGUF, which is memory-mapped from disk (obviously not from the floppy),
and runs from any directory:

```sh
./ds4-server --ctx 2048 -m /path/to/DeepSeek-V4-Flash.gguf
```

This branch targets the IQ2_XXS-experts / Q2_K-down Q2 quant of Flash 0731.

### Using it

Thinking is on by default and the sampling defaults are temperature 1, top-p 1
and min-p 0.05. The CLI and agent take `--nothink` / `--think` (`/nothink` in a
session) and `--temp 0` for greedy output; API clients set `think:false` and
`temperature` per request (see [serving](docs/SERVER.md)). `--power N` trades
throughput for lower sustained GPU load (default 100). The server's on-disk KV
store (`--kv-disk-dir`) is what makes long coding sessions practical.

DSpark speculative decoding is opt-in and needs a matching support GGUF; see
[speculative decoding](docs/SPECULATIVE_DECODING.md). Not every workload
benefits.

### What was removed, and how

The size comes from compiling features out and letting the linker drop them
(LTO plus `-ffunction-sections -fdata-sections` and `-Wl,-dead_strip`): other
models, vision, Engram, SSD streaming, distributed mode and tensor parallelism,
the CPU reference path, and the help text of the server. Code that only other
models or removed features used is deleted where it was cleanly separable; a few
one-line stubs and declarations keep the rest compiling.

TileLang kernels are always preferred at dispatch time. Every real op in the
server flow on this machine, including DSpark, is TileLang-covered: the only
hand-written kernels still dispatched are two no-op housekeeping kernels (a TP
keepalive and a warmup touch). Every other hand-written kernel is replaced by a
one-line no-op stand-in so availability checks and preconditions behave as
before; the build assembles the embedded kernel source from `prelude.metal` and
`gen/metal/` with `tools/assemble-metal-source.py`. If a workload ever
dispatches a stand-in for real work, `DS4_METAL_DUMMY_HAND_KERNELS=1` names it
in the exit report.

## Regenerating the TileLang kernels

Only needed when a kernel or TileLang itself changes, and only possible for the
fork's author: the `gen/metal/tl_*.metal` sources are checked in, so everything
above works from this repository alone. The kernels are generated from the
TileLang sources in `tilelang-kernels/` (see its
[README](tilelang-kernels/README.md) for the layout and prerequisites). With
the fork checked out at `~/tilelang` (branch `ds4-metal-cpu-reduce`):

```sh
cd ~/tilelang && git submodule update --init --recursive
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt -r requirements.txt
cmake -S . -B build -G Ninja -DUSE_CUDA=OFF -DUSE_LLVM=OFF -DUSE_METAL=ON \
      -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)   # ~2.5 minutes on an M5 Max
cd -                             # back in this repository
make gen-kernels                 # lowers tilelang-kernels/*.py to gen/metal/*.metal
make gen-check                   # verifies gen/ matches the sources
```

`gen/VERSION` records the TileLang commit. Codegen is host-side; no GPU is
required.

## Tests

Model-free checks that pass on this branch:

```sh
make test-tl-metal        # every generated Metal kernel vs a double-precision reference (needs the GPU)
make test-tl-cpu          # the generated C kernels vs the CPU reference
make test-session-state   # engine session state
make ds4_test && ./ds4_test --server   # server unit tests
```

With a model, `./ds4_test --logprob-vectors` checks against the official
DeepSeek logprobs in `tests/test-vectors/`. To confirm a run touches no
hand-written kernels, run the server with `DS4_METAL_DUMMY_HAND_KERNELS=1` and
read the report printed at exit.
